## Regras de Trabalho

### Estilo de Resposta

* Respostas diretas.
* Foco em implementação.
* Menos discussão teórica.
* Menos arquitetura especulativa.
* Mais código.
* Mais arquivos completos.
* Sempre fornecer arquivos completos quando houver alteração significativa.
* Evitar snippets parciais quando o arquivo inteiro será modificado.

### Solicitação de Arquivos

* Antes de modificar qualquer componente, solicitar os arquivos reais envolvidos.
* Não assumir estrutura.
* Não inventar arquivos existentes.
* Não criar arquitetura paralela sem verificar o projeto atual.

### Compatibilidade

* Preservar compatibilidade retroativa.
* Evitar breaking changes.
* Evoluir incrementalmente.

### Fundação do Projeto

* O documento de fundação evolui junto com o sistema.
* Mudanças conceituais devem refletir na fundação.
* Mudanças relevantes devem atualizar README e CHANGELOG.

### Filosofia de Desenvolvimento

Não estamos analisando um sistema.

Estamos construindo um sistema.

Prioridade:

1. Implementar.
2. Validar.
3. Corrigir.
4. Refatorar.
5. Documentar.

Discussões arquiteturais devem ser curtas e objetivas.

Quando existir informação suficiente para programar, programar.
